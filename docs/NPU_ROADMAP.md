# RK3566 NPU 轻量视觉路线

## 目标与边界

目标是在不影响 30fps 采集和推流稳定性的前提下，利用 RK3566 约 1 TOPS NPU 完成低频率、轻量化、本地运行的视觉判断。

第一阶段不做人脸身份识别，不默认保存原始图片，不把视频上传到云端。

## 推荐数据流

```text
Camera2
  ├─ Surface -> MediaCodec -> RTSP/WebRTC
  └─ ImageReader -> 降采样/限频 -> NPU Worker -> 事件状态
```

分析链路必须和编码链路解耦：

- 编码继续使用 Surface 零拷贝，不因视觉算法改回 CPU 全帧转换。
- ImageReader 使用独立低分辨率输出，队列深度保持 1，只处理最新帧。
- 初始分析频率建议 2～5fps；无人时可进一步降频。
- NPU Worker 不允许阻塞 Camera2 回调线程。

## 阶段 1：有人/无人

输入建议从 320×320 或更低分辨率开始，选择许可证清晰、可转换到 RKNN 的轻量检测模型。

输出：

- `personPresent`
- `confidence`
- `lastSeenAt`
- 可选的人体框；默认不持久化

验收重点：

- 摄像头推流帧率基本不受影响
- 连续运行稳定
- 逆光、夜视、局部遮挡下可接受
- 有明确的误报/漏报统计，而不是只展示单次演示

## 阶段 2：简单手势

建议采用两阶段轻量方案：

1. 手掌或手部区域检测
2. 对裁剪区域做少量静态手势分类

先支持 3～5 个差异明显的静态手势，避免一开始处理复杂动态轨迹。手势只触发本地动作，并增加持续时间、置信度和冷却时间，防止误触。

## 工具链与许可证

- RKNN Toolkit / Runtime 应由使用者从 Rockchip 官方渠道取得。
- 模型转换脚本可以开源，但不要把来源和许可证不清晰的模型权重提交到仓库。
- 每个模型都应记录来源、许可证、输入尺寸、量化方式和精度评估。
- 数据集涉及家庭场景时，应先做隐私清理并取得被拍摄者授权。

## 建议里程碑

1. 建立不接模型的抽帧和性能测量骨架。
2. CPU 上跑通一个许可证清晰的基线模型。
3. 转换 RKNN 并验证输出一致性。
4. 接入 NPU Runtime，记录时延、CPU、内存和温度。
5. 与推流并行运行 24 小时稳定性测试。
6. 再接事件通知或手势控制。
