# 宝宝守护处理逻辑、校准与健康诊断

## 处理顺序

动作和哭声是两条独立的触发链路，NPU 是通知前的陪护上下文，不是宝宝身份分类器。

```text
动作达阈值 或 YAMNet 疑似哭声达阈值
                │
                ├─ 请求下一张相机帧
                └─ 同一 NPU 单线程队列补跑，最多等待 300ms
                               │
             ┌── 当前检出两人或成人体型证据 ──┐
             │                                         │
          是：记录，不通知                  否/不可用：按安全侧保持通知武装
             └─────────────────────────────────────────┘
                               │
                  写入或合并 60 秒事件会话
                               │
                    首次创建短片，最多通知一次
```

如果新帧、NPU 或 300ms 等待任一环节失败，事件仍会记录。系统会在事件原因中写明 `timeout`、`unavailable` 或使用最近画面，而不会把“没有视觉结果”解释为“没有宝宝”。

第一次端到端 NPU 推理通常比后续推理慢。开启守护时会在启动动作和哭声触发器之前做自适应预热：首先等待 Camera HAL 的新帧（最多 5 秒），然后至少推理两轮、最多四轮，当单轮降到 250ms 以内即结束，整个启动预热的总等待上限 8 秒。多轮预热即使复用同一帧，也只把最后一轮作为一次陪护观测，避免人为放大同一画面的成人证据。常规轮询的首轮延后到守护启动约 5 秒，避免与 YAMNet 初始化争用 CPU。这不改变真实告警的 300ms 等待上限和后续每 2 秒轮询频率。

## 陪护证据边界

- COCO `person` 只能检出通用人体，不能识别年龄、亲属关系或宝宝身份。
- 当前帧两人及以上，或至少一个人体框符合固定机位的成人体型启发式，会立即抑制当次通知。
- 最近 4 次中 3 次存在陪护证据时，状态稳定确认为“有人陪护”；证据消失约 20 秒后恢复通知。
- 单人、人体未检出、睡姿、床铺区域或重点动作区域都不能确认身份。

## 场景校准

### 房间底噪

1. 开启宝宝守护，确认 YAMNet 已加载。
2. 保持房间平时的安静状态，开始约 15 秒校准。
3. 设备对每个 0.975 秒窗口计算 RMS 和哭声分数，保存高分位统计，并为当前灵敏度留出余量。
4. 校准期间不触发哭声事件，不保存 PCM、录音或分类全量输出。

### 成人常见站位

1. 画面中只保留一名成人，站在平时常用的陪护位置。
2. 系统收集 8 次单人框的归一化高度和面积；检出 0 人或多人时不计入进度。
3. 只保存中位统计和带坐姿/距离余量的阈值，不保存截图、人体框序列或身份。

校准值可在页面一键恢复默认。校准不能把启发式变成年龄识别，仍需通过事件反馈观察误报。

## 事件反馈

每个动作/哭声会话可选择：

- 确实需要关注；
- 误报；
- 成人在场。

反馈只保存标签和标记时间，可以改选。当前版本不自动调整底噪、哭声、动作或成人体型阈值。

## 滚动 24 小时健康诊断

设备每 60 秒保存一条轻量样本，最多保留 1,500 条，并按时间滚动删除 24 小时以外的数据。记录包括：

- 摄像头是否应该运行、JPEG 是否在 5 秒内更新、编码是否就绪和样本间帧率；
- 守护应该运行时，NPU 是否加载、是否在 7 秒内更新、最近推理耗时；
- 守护应该运行时，YAMNet 是否加载、音频分析是否在 5 秒内更新；
- 服务启动次数、应用可用存储、短片占用及其变化。

主动隐私模式会被排除在摄像头故障率之外；宝宝守护关闭期间不对 NPU 和音频新鲜度计故障。当前样机 Thermal HAL 不可用，页面会明确说明，健康结论不依赖缺失的温度数据。

## 端侧存储与 API

| 内容 | 应用私有目录 | 页面/API |
| --- | --- | --- |
| 事件解释和反馈 | `files/guardian-events/events.json` | `/api/events` |
| 事件 MP4 | `files/guardian-events/clips/` | `/event-clip`、`/api/events` |
| 24 小时健康统计 | `files/health-diagnostics/rolling-24h.json` | `/api/health` |
| 底噪与体型阈值 | Android `SharedPreferences` | `/api/calibration` |

卸载应用或清除应用数据会删除上述内容。仓库的 `.gitignore` 排除事件短片、音频、模型、校准媒体和设备数据；不应将真实家庭数据放入源码提交、Issue 或 Release。
